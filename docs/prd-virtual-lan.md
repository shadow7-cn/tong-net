# 同网互通虚拟局域网与自建组网服务 PRD

> 状态：草案，等待评审  
> 关联产品：同网互通桌面端、同网互通组网管理服务、EasyTier  
> 目标平台：Windows、macOS、Linux Docker

## 问题背景

当前同网互通只适用于同一个真实局域网。位于不同家庭、办公室或城市的电脑，即使都安装了同网互通，也无法直接发现和访问彼此。普通用户虽然可以自行安装 EasyTier 等虚拟组网工具，但需要理解节点、虚拟 IP、网络名称、密钥、中继和命令行参数，使用门槛较高。

希望使用自有服务器的用户还需要分别部署组网节点、管理后台和账号系统，缺少一套面向普通用户的完整方案。他们希望只部署一个 Docker 服务，在图形化后台完成初始化、账号管理和在线设备查看；桌面端用户只填写服务器地址、账号、密码和自己的设备名称，即可加入虚拟局域网。

本功能要解决的是：

- 让不同真实网络中的同网互通桌面端组成一个私人虚拟局域网。
- 隐藏 EasyTier 的命令行参数和底层组网概念。
- 允许用户在自己的 Linux 服务器上部署和管理整套服务。
- 保持聊天和文件尽量点对点传输，控制服务不保存用户聊天和文件内容。

## 方案概述

同网互通新增“虚拟局域网”能力，由桌面端、Linux 组网管理服务和 EasyTier 网络层共同组成。

### 桌面端

Windows 和 macOS 版同网互通内置并管理 EasyTier Core。左侧新增“虚拟局域网”入口，用户填写：

1. 服务器地址
2. 访问账号
3. 访问密码
4. 自定义设备名称

登录成功后，桌面端从组网管理服务取得该账号被授权使用的虚拟网络及短期设备凭据，自动启动 EasyTier、加入网络并获得虚拟 IP。普通用户不需要接触网络名称、网络密钥、节点 URI 或 EasyTier 命令行。

### Linux 组网管理服务

管理员使用 Docker Compose 在有公网访问能力的 Linux 服务器上部署服务。服务包含：

- Web 管理后台
- 管理与设备接入 API
- 数据库
- EasyTier 配置下发能力
- EasyTier 公共节点和必要的中继能力

首次打开后台时必须创建管理员账号和密码。进入后台后，管理员可以创建虚拟局域网、访问账号和设备授权，并查看当前连接用户、设备、虚拟 IP、在线状态、连接方式、延迟和流量概况。

EasyTier 本身是去中心化 Mesh 网络，没有固定的传统“VPN 服务端”。Linux 节点主要负责设备发现、配置下发、NAT 穿透协助和穿透失败时的中继。节点能够直接连接时，聊天和文件流量应优先 P2P，不经过管理 API。

EasyTier 已提供可自建的 Web API、Web 控制台和配置下发服务。本项目应优先复用其稳定能力，在其上增加同网互通需要的首次初始化、访问账号、设备身份和产品化管理界面，而不是重新实现 Mesh VPN。[EasyTier Web 控制台文档](https://easytier.cn/guide/network/web-console.html)

## 产品目标

1. 普通用户无需了解 EasyTier 即可加入虚拟局域网。
2. 管理员可以通过 Docker 快速部署完整的自建服务。
3. 一套部署可以管理多个虚拟局域网、访问账号和设备。
4. 用户可以自定义设备名称，并在桌面端和管理后台保持一致。
5. 同网互通可以通过虚拟网络发现和访问其他已授权桌面端。
6. 节点之间优先 P2P，无法直连时才使用 Linux 节点中继。
7. 控制服务只管理账号、设备、网络和连接元数据，不保存聊天与文件内容。
8. 设备凭据可撤销，离职、丢失或异常设备可以立即禁止继续接入。

## 非目标

本功能不是公共云网盘、聊天云服务或匿名公网代理。项目不为用户统一运营中心服务器，也不承诺绕过所有网络限制。自建服务器的带宽、稳定性、域名、证书和运维由部署者负责。

## 核心概念

### 管理员

部署 Linux 服务并管理整个站点的人。管理员账号只用于管理后台，不直接作为桌面端组网凭据。

### 访问账号

管理员为使用者创建的账号。一个访问账号可以被授权加入一个或多个虚拟局域网，也可以拥有多台设备。

### 设备

一次桌面端安装对应一个稳定的内部设备 ID。设备包含：

- 设备 ID：系统生成，不允许用户修改
- 设备名称：用户设置，可以修改
- 管理员备注：管理员设置，不覆盖用户设备名称
- 所属访问账号
- 操作系统与客户端版本
- 虚拟 IP
- 在线状态与最后在线时间
- 连接方式、延迟和流量概况
- 创建时间、禁用状态和凭据状态

设备名称允许重复，系统始终使用设备 ID 区分真实身份。重装或清空应用身份后，默认视为一台新设备。

### 同网互通主机名称

现有局域网聊天和文件页面展示的名称。第一版默认与虚拟局域网设备名称相同，但允许用户分别修改，避免把底层设备身份与聊天展示名称永久绑定。

### 虚拟局域网

由管理员创建的隔离网络。只有被授权的访问账号和设备可以加入。不同虚拟局域网之间默认不能互相访问。

### 组网凭据

由系统签发并交给 EasyTier 使用的设备凭据。访问账号密码只用于登录管理服务，不直接作为 EasyTier 网络密钥。桌面端不向普通用户展示长期网络密钥。

## 用户流程

### 管理员首次部署

1. 管理员准备具有公网访问能力的 Linux 服务器。
2. 下载项目提供的 Docker Compose 配置并启动服务。
3. 浏览器打开管理地址。
4. 系统检测到未初始化，要求创建管理员账号和强密码。
5. 管理员设置站点名称、公开地址和必要端口。
6. 系统完成初始化并关闭首次设置入口。
7. 管理员创建虚拟局域网。
8. 管理员创建访问账号并授予网络权限。
9. 管理员将服务器地址和访问账号交给用户。

### 桌面端首次加入

1. 用户打开同网互通的“虚拟局域网”页面。
2. 输入服务器地址、访问账号和密码。
3. 输入或确认自己的设备名称。
4. 登录成功后选择有权加入的虚拟局域网。
5. 服务端登记设备并签发设备凭据。
6. 桌面端启动 EasyTier 并加入网络。
7. 页面显示虚拟 IP、在线成员和连接状态。
8. 用户点击目标设备，进入远程同网互通入口。

### 后续自动连接

1. 同网互通启动。
2. 从系统凭据库读取已保存的登录信息或设备凭据。
3. 获取最新网络配置并检查设备是否仍被授权。
4. 自动启动 EasyTier。
5. 连接成功后刷新在线成员和目标服务状态。

### 设备禁用

1. 管理员在后台禁用设备或撤销凭据。
2. 控制服务拒绝该设备刷新凭据。
3. 在线设备在合理时间内收到状态变化并断开。
4. 被禁用设备再次连接时显示明确原因。

## 实现决策

- 同网互通继续采用 Monorepo，新增 Linux 管理服务和管理 Web，不把服务端代码塞进桌面应用。
- 桌面端继续使用 Tauri、React 和 Rust，并由 Rust 层管理 EasyTier 子进程、配置文件、日志和退出清理。
- EasyTier 以独立可执行文件或受控子进程集成，不直接复制和改写其核心网络实现。
- Windows 和 macOS 安装包必须携带对应架构的 EasyTier Core，并记录上游版本和许可证。
- Linux 服务优先复用 `easytier-web`、配置下发协议和 EasyTier 公共节点能力；同网互通服务负责产品账号、设备、授权和管理体验。
- EasyTier 的网络名称、长期密钥和底层连接参数不直接暴露给普通桌面用户。
- 访问账号密码用于控制服务认证；EasyTier 使用单独的设备凭据。
- 优先评估 EasyTier Secure Mode 的可撤销、短期或一次性凭据，避免向所有设备分发同一个永久网络密钥。EasyTier 从 v2.6 起提供了更完整的安全接入和凭据撤销能力。[EasyTier Release 说明](https://github.com/EasyTier/EasyTier/releases)
- 管理员账号、访问账号和设备凭据必须分离。
- 密码只保存强哈希；桌面端敏感信息保存到操作系统凭据库。
- 设备名称由用户设置，管理员备注独立保存，设备身份以不可变设备 ID 为准。
- 一个访问账号可以拥有多台设备；设备数量可由管理员限制。
- 一套管理服务可以创建多个虚拟局域网，账号按网络授权。
- 不启用虚拟局域网时，不启动 EasyTier，不影响原有真实局域网模式。
- 虚拟局域网模式下，远程同网互通访问必须认证，不允许依赖现有“允许无令牌访问”开关。
- 远程聊天和文件仍由目标同网互通主机处理和保存；管理服务不成为消息或文件业务服务器。
- P2P 失败时允许通过自建 EasyTier 节点中继，并在界面明确展示当前连接方式。
- 第一版桌面端之间的远程访问以“发现目标主机并进入其同网互通入口”为主，不在控制服务中建立云端会话。
- 管理 API 与配置下发接口分开授权和限流。
- 公网生产部署必须使用 HTTPS；纯 HTTP 只允许首次本机调试或明确的内网部署。
- 服务端记录必要的账号、设备、授权、在线状态和审计元数据，不记录用户聊天内容、文件内容或文件名。
- EasyTier 使用 LGPL-3.0，发布时必须保留许可证、上游声明，并评估修改或链接方式对应的开源义务。[EasyTier 项目与许可证](https://github.com/EasyTier/EasyTier)

## 数据与权限

### 主要数据实体

- Site：站点初始化状态和公开配置
- AdminUser：管理员身份
- AccessUser：访问账号
- VirtualNetwork：虚拟局域网
- NetworkMembership：账号对网络的授权
- Device：设备身份、名称和元数据
- DeviceCredential：可撤销的设备凭据
- DeviceSession：在线状态和连接元数据
- AuditLog：管理员和关键设备操作

### 权限规则

- 管理员可以管理本站全部网络、账号和设备。
- 访问账号只能看到自己被授权的网络。
- 普通用户只能管理自己的设备名称和登录状态。
- 用户不能查看其他账号的登录信息或设备凭据。
- 同一虚拟局域网的成员只能看到建立连接所需的最小设备信息。
- 被禁用账号下的所有设备停止获取新凭据。
- 被禁用设备不能影响同账号下的其他正常设备。

## 安全要求

- 首次初始化必须只能完成一次。
- 不提供固定管理员默认密码。
- 管理员密码和访问密码使用适合密码存储的强哈希算法。
- 登录接口具有速率限制和失败审计。
- 支持撤销单个设备凭据，不要求全网更换共享密钥。
- 敏感字段不写入普通日志。
- Docker Secret 或等价机制优先用于服务器密钥。
- 桌面端不以明文文件保存访问密码和长期设备凭据。
- 管理后台生产环境使用 HTTPS 和安全 Cookie。
- 配置下发和设备状态上报必须鉴权。
- 虚拟局域网模式不能默认开启无令牌 HTTP 访问。
- 管理服务被攻破时，应尽量避免攻击者直接取得历史聊天和文件，因为这些内容不在服务器保存。
- 中继流量应使用 EasyTier 提供的加密能力，管理服务不解密业务内容。

## 兼容性与边界

- Windows 和 macOS 同网互通桌面端是第一阶段正式客户端。
- Linux 第一阶段只提供 Docker 组网管理服务，不提供完整同网互通桌面 UI。
- 浏览器不能仅凭打开网页加入 EasyTier 虚拟网络。
- 手机浏览器仍需与某台同网互通主机处于同一真实局域网，或手机本身通过 EasyTier/WireGuard 等方式加入虚拟网络。
- 第一版不承诺 iOS、Android 浏览器在无额外客户端时直接跨公网访问虚拟 IP。
- EasyTier 支持把节点作为 WireGuard 入口，手机接入可以作为后续独立版本规划，而不是混入第一版。[EasyTier WireGuard 能力说明](https://github.com/EasyTier/EasyTier)

## 验收标准

1. 全新 Linux 服务器可以通过文档中的 Docker Compose 命令启动完整服务。
2. 未初始化服务只能进入首次设置页，初始化完成后不能再次创建首个管理员。
3. 管理员可以创建虚拟局域网、访问账号并完成授权。
4. 两台位于不同真实网络的桌面电脑可以使用同一服务登录。
5. 两台电脑可以分别设置自己的设备名称，并在管理后台正确显示。
6. 两台设备获得不同且稳定的内部设备 ID。
7. 两台设备加入同一个虚拟局域网后可以互相发现。
8. 界面能够显示虚拟 IP、在线状态和 P2P/中继状态。
9. 用户点击远程设备后可以访问其同网互通入口，并完成文字消息传递。
10. 用户可以通过虚拟网络完成文件上传和下载。
11. P2P 可用时，业务数据不经过管理 API。
12. P2P 不可用时，可以通过自建 EasyTier 节点完成中继传输。
13. 禁用设备后，该设备不能继续刷新凭据或重新加入。
14. 修改用户设备名称不会改变设备 ID，也不会创建新设备。
15. 重启桌面端后可以按配置自动重新连接。
16. 重启或升级 Docker 容器后，账号、网络、设备和授权数据仍然存在。
17. 未启用虚拟局域网的用户仍可完整使用现有局域网功能。
18. 管理服务的数据库和日志中不出现聊天正文和文件内容。

## 测试决策

- 最高层测试接缝是一套可自动运行的真实组网验收环境：一个 Docker 管理服务、两个独立 EasyTier 桌面节点和两个不同网络命名空间。核心验收通过公开 API、虚拟 IP 连通性和同网互通 HTTP/WebSocket 行为完成，不依赖内部函数。
- 管理服务测试覆盖首次初始化、管理员认证、访问账号、网络授权、设备登记、凭据签发、禁用和审计。
- 桌面端测试覆盖 EasyTier 生命周期状态机：未配置、登录中、获取配置、启动中、已连接、重连中、凭据失效和已断开。
- 设备名称测试覆盖默认值、用户修改、重复名称、长度限制、控制字符和重启持久化。
- 组网测试覆盖 P2P 成功、P2P 失败后中继、服务端暂时离线、配置下发重连和设备凭据撤销。
- 安全测试覆盖错误密码限流、越权访问其他网络、禁用账号、禁用单设备、过期凭据和敏感日志检查。
- Docker 测试覆盖首次启动、健康检查、数据卷持久化、版本升级和备份恢复。
- 同网互通回归测试继续覆盖局域网服务、聊天、文件上传、取消、Range 下载和本地记录。
- 前端端到端测试覆盖管理员首次设置、创建网络和账号、桌面端登录、设置设备名称、查看在线设备和断开连接。
- 测试只断言用户和外部接口可观察的行为，不绑定 EasyTier 内部实现细节。

- 官方运营的公共同网互通云服务

- 云端保存、扫描或转发用户文件
- 浏览器直接运行 EasyTier
- 无客户端的手机公网直连
- 第一版手机原生 App
- 第一版多管理员复杂 RBAC

- 第一版匿名注册或开放自助注册

- 保证所有 NAT 和防火墙环境都能 P2P 直连

## 风险与待确认项

1. EasyTier Secure Mode、Web API 和配置下发接口是否足以承载本项目的账号到设备凭据流程，需要先做技术原型验证。
2. Windows 和 macOS 启动虚拟网卡通常需要管理员权限，首次授权体验需要单独设计。
3. macOS Network Extension 的签名、权限和发布方式可能提高 Apple 开发者账号与公证要求。
4. EasyTier Core 的 LGPL-3.0 合规方式需要在正式分发前确认并写入第三方声明。
5. 中继大文件会消耗 Linux 服务器带宽，后台需要明确展示并允许管理员限制。
6. “点击远程设备直接进入会话”的认证协议需要在 TRD 中确定，不能复用无令牌访问。
7. 多虚拟局域网同时连接、虚拟 IP 冲突和本地真实网段冲突需要明确处理策略。
8. 管理服务升级 EasyTier 版本时，需要处理旧桌面客户端的兼容范围。

## 补充说明

该功能会把同网互通从“同一个 Wi-Fi 下的临时传输站”扩展为“可自建的私人虚拟局域网与跨网络传输工具”，但应继续保持原有产品原则：

- 免费、开源、可自建
- 默认不采集用户内容
- 普通用户不需要理解底层网络术语
- 不启用远程组网时仍可完全离线使用
- 控制平面负责身份和配置，数据平面优先点对点

PRD 通过后，下一步应先针对 EasyTier 管理接口、Secure Mode、跨主机认证和 Tauri 子进程权限做技术原型，再输出 TRD 和可独立实施的开发任务。
